## 2024-07-04 - Balancing Event Loop and Memory Limits in Batch Uploads
**Learning:** When batch processing multiple large files (like an array of up to 50 images in the `/api/image-to-pdf` endpoint), using `fs.readFileSync` completely blocks the Node.js event loop, paralyzing the server for all other users. However, switching to a purely concurrent approach like `Promise.all(files.map(f => fs.promises.readFile(f)))` causes severe memory spikes and potential Out of Memory (OOM) crashes by loading all files into RAM simultaneously.
**Action:** Always use sequential asynchronous processing (e.g. `await fs.promises.readFile` inside a `for...of` loop) for endpoints handling multi-file uploads in this codebase. This correctly unblocks the event loop while keeping memory consumption stable and predictable.
