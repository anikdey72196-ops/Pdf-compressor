## 2024-07-10 - Synchronous file operations blocking Event Loop in batch processing
**Learning:** In the `/api/image-to-pdf` endpoint, using `fs.readFileSync` inside a loop while processing potentially large batches of images (up to 50) sequentially blocks the Node.js event loop, preventing the server from handling other requests. While sequential processing helps prevent OOM errors (as opposed to concurrent `Promise.all()`), it's crucial to use asynchronous operations like `await fs.promises.readFile()` to keep the event loop non-blocked during the file I/O phase.
**Action:** Always prefer asynchronous file operations (`fs.promises`) over synchronous ones (`fs.readFileSync`, `fs.writeFileSync`), especially when iterating over multiple files, to ensure the application remains responsive to other requests.
